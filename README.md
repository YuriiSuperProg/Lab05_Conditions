## Фрагмент кода: функция GetHint()

В рамках игры «Угадай число» была реализована функция подсказки, использующая `switch` для определения «температуры» (холодно/тепло/горячо) в зависимости от разницы между введенным и загаданным числом.
```csharp
string GetHint(int difference)
switch (difference)
{
    case <= 3:
        return "🔥 Горячо!";
    case <= 10:
        return "🌡️ Тепло.";
    case <= 25:
        return "⛄️ Прохладно.";
    default:
        return "❄️ Холодно!";
}
```

1. Условные операторы — основа логики. Конструкции `if/else` и `switch` позволяют программе принимать решения в зависимости от входных данных, что делает поведение программы гибким.

## Ответы на контрольные вопросы

1. **Чем` int.TryParse()` безопаснее `int.Parse()`? В каких случаях стоит использовать каждый?**

`int.Parse()` выбрасывает исключение `FormatException`, если строка не может быть преобразована в число. Это приводит к аварийному завершению программы, если не использовать блок `try-catch`. `int.TryParse()` возвращает `true` или `false` и записывает результат в переменную через `out`-параметр. Это безопаснее, так как программа не падает.

* `int.TryParse()` стоит использовать при вводе данных от пользователя (где возможны опечатки).
* `int.Parse()` можно использовать, если вы на 100% уверены в формате данных (например, при чтении из проверенного файла).

2. **Когда `switch` удобнее, чем цепочка `if/else if`? Приведите пример из реальной жизни.**

`switch` удобнее, когда нужно сравнить одну переменную с набором конкретных, заранее известных значений. Это делает код более читаемым и структурированным.

* Пример из жизни: Меню в банкомате. Пользователь нажимает кнопку «1» — «Снять наличные», «2» — «Оплатить услуги», «3» — «Проверить баланс». Здесь используется `switch` по номеру нажатой кнопки.

3. **Что произойдёт в `switch`, если убрать `break` после одного из `case`?**

Произойдет «проваливание» (fall-through). Выполнение кода продолжится в следующем блоке `case`, даже если его условие не совпало. В C# это часто используется намеренно, когда несколько `case` должны выполнять одно и то же действие (например, `case 1: case 2: case 3: ...`). Однако если это случайная ошибка, программа выполнит лишний код.

4. **Чем отличается `=` от `==`в C#? Почему это частая ошибка?**

* `=` — это оператор присваивания. Он записывает значение в переменную (например, `x = 5`).
* `==` — это оператор сравнения. Он проверяет, равны ли два значения, и возвращает `true` или `false` (например, `x == 5`).
Это частая ошибка новичков, потому что в математике знак равенства один, и мозг автоматически ставит его в условии `if (x = 5)`. В C# это приведет либо к ошибке компиляции (если типы не совпадают), либо к логической ошибке (если присваивание допустимо, и условие всегда будет истинным).
